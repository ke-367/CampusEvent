## 二、评审检查项

| 序号 | 检查项 | 判断标准 | 结论（符合/不符合） | 意见 |
| --- | --- | --- | --- | --- |
| 1 | 用例覆盖完整性 | 报名三种规则、审批、取消、通知、下架均有对应用例 | | |
| 2 | 类职责单一性 | 每个类能用一句话说清职责，无“万能类” | | |
| 3 | 依赖方向 | 依赖单向（web→service→domain/repository），无循环依赖 | | |
| 4 | 策略模式可替换性 | 三种规则实现同一接口，主流程无类型判断 | | |
| 5 | 名额规则归属 | 名额口径唯一实现，检查时机由策略决定，理由成立 | | |
| 6 | 观察者解耦 | 业务只发事件，通知为订阅者；失败不影响主事务 | | |
| 7 | 时序图正确性 | 事务提交与事件发布顺序、失败分支清晰 | | |
| 8 | 可测试性 | 每个关键规则都有对应测试用例编号 | | |
